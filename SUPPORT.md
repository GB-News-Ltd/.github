# Support

## Not sure where to go?

| Need | Where |
|------|--------|
| Bug in a product/repo | GitHub **Bug report** issue on that repo |
| Feature idea | GitHub **Feature request** |
| Production / staging emergency | `hotfix/*` from `master` + **Incident / SEV** issue |
| Branching / protection questions | [docs/handbook/branching.md](docs/handbook/branching.md) |
| Security vulnerability | [SECURITY.md](SECURITY.md) — not a public issue |
| Access / permissions | Internal IT / identity request (staff) |
| "How do we do X here?" | [docs/handbook/](docs/handbook/README.md) or Platform Engineering |

## Tickets & Jira

Branches use `<type>/<ticket-id>-<slug>`. The ID may be **Jira, Linear, or a GitHub issue** — Jira specifically is optional. GitHub remains the source of truth for code review and CI.

## Response expectations

- Triage labels (`triage`) are cleared by the owning team during their normal cadence.
- SEV / incident issues follow on-call SLAs, not the backlog cadence.
- `emergency-merge` PRs are reviewed in the next sprint retro.
